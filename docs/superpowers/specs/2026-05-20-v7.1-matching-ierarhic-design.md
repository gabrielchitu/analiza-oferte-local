**Data:** 2026-05-20  
**Branch:** `feature/7.1` (creat din `feature/7.0`)  
**Prerequisit:** v7.0 complet (nr_ordine, display_parent_cod, raport ierarhic)

## Problema de rezolvat

În v7.0, `$6720287` (ofertă, copil al CK25A) este fuzzy-matchuit greșit la `CK26A` (articol normativ diferit) cu score=0.54 pe cuvântul "pvc". Articolul apare ca "matched" în loc de EXTRA. Articolul de referință corespunzător (`$6720289`, același CK25A) apare ca LIPSA în loc de perechea corectă LIPSA+EXTRA.

**Cauza rădăcină:** `display_parent_cod` este asignat din ordinea extracției PDF, care diferă între documentul de referință și cel de ofertă. Cheia `(deviz, display_parent_cod, $cod)` nu este consistentă între documente pentru același articol.

**Exemplu concret:**
- Ref: `$2608118` cu `display_parent_cod=RPIF09C` (extracție ref)
- Ofertă: `$2608118` cu `display_parent_cod=RPIF09C` ← OK dacă PDFurile au aceeași structură
- Dar: `$2608118` cu `display_parent_cod=ALTCEVA` ← fail dacă structura diferă

---

## Soluția v7.1 — Catalog Normativ din Referință

**Principiu:** Referința este sursa de adevăr pentru maparea `$resource_cod → normative_cod`. Construim un catalog din referință și îl folosim ca indice canonical. Oferta nu mai contribuie cu `display_parent_cod` la cheia de matching — doar la display.

### Catalog normativ

```python
# ref_catalog: {$cod → normative_cod} extras din referință
# Construit din articolele referinței care au display_parent_cod setat
ref_catalog = {
    "$6720289": "CK25A",
    "$6720301": "CK25A",
    "$2608118": "RPIF09C",
    "$2608119": "RPIF09C",
    ...
}
```

**Construcție:** din `ref_articole` unde `display_parent_cod` este setat (via `_apply_parent_inheritance`).

**Cheia Layer 0:** `(deviz, ref_catalog[$cod], $cod)` — parent din catalog, nu din PDF.

### Algoritmul complet

```
LAYER 0 (nou):
  1. Construiește ref_catalog din referință:
       ref_catalog[$cod] = display_parent_cod (pentru toate $ din ref cu parent cunoscut)

  2. Separă din ref_dedup și oferta_dedup articolele $ cu parent în catalog:
       ref_subarticole = [a for a in ref_articole if a.cod in ref_catalog]
       oferta_subarticole = [a for a in oferta_articole
                             if a.cod in ref_catalog]  ← catalog din REF, nu din ofertă!

  3. Prima parcurgere (ref → ofertă):
       For each ref_art in ref_subarticole:
           key = (ref_art.deviz, ref_catalog[ref_art.cod], ref_art.cod)
           Dacă key în oferta_hier_index → MATCHED (cu diferențe dacă există)
           Altfel → ARTICOL_LIPSA

  4. A doua parcurgere (ofertă → ref):
       For each oferta_art in oferta_subarticole (nematchuite):
           → ARTICOL_EXTRA (cu oferta_display_parent_cod pentru display)

  5. Articole $ din ofertă CARE NU SUNT ÎN ref_catalog:
       → ARTICOL_EXTRA direct (cod complet nou, nu există în referință)

LAYER 1-4 (neschimbate):
  Procesează articolele principale (non-$) și $ fără parent în catalog.
```

### Cum rezolvă cazul `$6720287`

```
ref_catalog: {"$6720289": "CK25A", "$6720301": "CK25A", ...}

Ref subarticole: [$6720289, $6720301, ...]
Ofertă subarticole (cod in ref_catalog): []
  → $6720287 NU este in ref_catalog (ref nu are $6720287)
  → $6720287 merge la "ofertă $ fără parent în catalog" → ARTICOL_EXTRA ✓

Ref $6720289 (key=(4.1-03, CK25A, $6720289)):
  → nu găsit în ofertă → ARTICOL_LIPSA ✓

Rezultat: $6720289 LIPSA + $6720287 EXTRA — vizibil în raport!
```

### Cum rezolvă cazul `$2608118` (același cod în ref și ofertă)

```
ref_catalog: {"$2608118": "RPIF09C"}

Ref $2608118: key=(4.1-10, RPIF09C, $2608118)
Ofertă: $2608118 este in ref_catalog (same cod)
  → oferta_hier_index[(4.1-10, RPIF09C, $2608118)] = oferta_art
  → MATCHED ✓ (indiferent de display_parent_cod din ofertă)
```

## Schimbări față de v7.0

### Schimbare 1: `build_ref_catalog` în `shared/report_builder.py` sau `AgentComparator_local.py`

```python
def build_ref_catalog(ref_articole: list) -> dict:
    """Catalog canonical: $cod → normative_cod, extras din referință.

    Sursa de adevăr pentru parent mapping. Ignoră display_parent_cod din ofertă.
    """
    catalog = {}
    for art in ref_articole:
        cod = art.get('cod', '')
        parent = art.get('display_parent_cod')
        if cod.startswith('$') and parent:
            catalog[cod] = parent
    return catalog
```

### Schimbare 2: Layer 0 în `AgentComparator_local.py:match_global`

Adăugat înainte de Layer 1. Articolele din `ref_subarticole` și `oferta_subarticole` sunt EXCLUSE din `ref_dedup`/`oferta_dedup` (nu participă la Layer 1-4).

```python
# Separare subarticole
ref_catalog = build_ref_catalog(ref_articole)

ref_subarticole = []
ref_dedup_main = []
for a in ref_articole:
    if (a.get('cod', '').startswith('$')
            and a.get('cod') in ref_catalog
            and not a.get('is_component')
            and not _is_breviar_artifact(a)):
        ref_subarticole.append(a)
    elif not a.get('is_component') and not _is_breviar_artifact(a):
        ref_dedup_main.append(a)

oferta_subarticole_catalog = []  # $ coduri din ofertă care există în ref_catalog
oferta_subarticole_new = []      # $ coduri din ofertă care NU există în ref_catalog → EXTRA direct
oferta_dedup_main = []
for a in oferta_articole:
    if not _is_breviar_artifact(a):
        if a.get('cod', '').startswith('$') and a.get('cod') in ref_catalog:
            oferta_subarticole_catalog.append(a)
        elif a.get('cod', '').startswith('$') and not a.get('is_component'):
            oferta_subarticole_new.append(a)  # complet nou → EXTRA
        else:
            oferta_dedup_main.append(a)

# Indexare ofertă subarticole (cheie cu parent DIN CATALOG, nu din ofertă)
oferta_hier: dict = {}  # (deviz, parent_din_catalog, $cod) → oferta_art
for a in oferta_subarticole_catalog:
    parent = ref_catalog[a.get('cod')]  # ← din catalog, nu din display_parent_cod
    key = (a.get('deviz', ''), parent, a.get('cod', ''))
    if key not in oferta_hier:
        oferta_hier[key] = a

# Layer 0 matching
oferta_matched_hier = set()
for ref_art in ref_subarticole:
    parent = ref_catalog[ref_art.get('cod')]
    key = (ref_art.get('deviz', ''), parent, ref_art.get('cod', ''))
    deviz_cod = ref_art.get('deviz', '')
    deviz_den = ref_art.get('deviz_denumire', '')

    oferta_art = oferta_hier.get(key)
    if oferta_art is not None:
        oferta_matched_hier.add(id(oferta_art))
        diffs = compare_articles(ref_art, oferta_art, include_prices=include_prices)
        arith = check_arithmetic(oferta_art) if include_prices else []
        for d in diffs + arith:
            _enrich(d, ref_art, oferta_art, deviz_cod, deviz_den)
        neconformitati.extend(diffs + arith)
        matches.append({
            "ref_cod": ref_art.get("cod", ""),
            "ref_denumire": ref_art.get("denumire", ""),
            "oferta_cod": oferta_art.get("cod", ""),
            "oferta_denumire": oferta_art.get("denumire", ""),
            "deviz": deviz_cod,
        })
    else:
        nc = {"tip": "ARTICOL_LIPSA"}
        _enrich(nc, ref_art, None, deviz_cod, deviz_den)
        neconformitati.append(nc)

# Ofertă nematchuită → EXTRA
for oferta_art in oferta_subarticole_catalog:
    if id(oferta_art) in oferta_matched_hier:
        continue
    _add_extra_nc(neconformitati, oferta_art)

for oferta_art in oferta_subarticole_new:
    _add_extra_nc(neconformitati, oferta_art)
```

Unde `_add_extra_nc` e funcție helper care construiește nc-ul ARTICOL_EXTRA (extrage logica existentă din blocul de la linia ~865).

## Cazuri speciale

### Același `$` cod în devize diferite
Cheia include `deviz` → nu există coliziuni. Un `$2608118` în deviz `4.1-10` ≠ `$2608118` în deviz `4.1-11`.

### `$` cod cu parent în catalog dar deviz diferit ref vs ofertă
- Ref: `$6720301` în `4.1-03` → Layer 0 caută în ofertă la `(4.1-03, CK25A, $6720301)`
- Ofertă: `$6720301` în `4.1-04` → nu găsit la key `(4.1-03, CK25A, $6720301)`
- Rezultat: LIPSA în ref + EXTRA în ofertă (corect — deviz greșit)

### `$` cod cu multiple apariții în același deviz (N:M)
Posibil dacă același normativ apare de 2× cu cantități diferite. Layer 0 folosește N:M similar cu Layer 1: sortare după cantitate + best-first pairing.

### Articole is_component=True (subarticole explicite)
Rămân excluse din `ref_dedup` (ca în v7.0). Dacă `is_component=True` ȘI `cod in ref_catalog` → Layer 0. Dacă `is_component=True` ȘI `cod NOT in ref_catalog` → ignorat (breviar artifact sau cod complet nou).

## Criterii de succes

1. `$6720287` apare ca ARTICOL_EXTRA în ofertă 1, deviz 4.1-03
2. `$6720289` apare ca ARTICOL_LIPSA în ofertă 1, deviz 4.1-03
3. `$2608118`, `$2608119` etc. rămân MATCHED (sunt în ref_catalog cu parent RPIF09C)
4. Metrici globale: `matched` nu scade față de v7.0 (1041/1060)

## Riscuri

| Risc | Probabilitate | Mitigare |
|------|--------------|---------|
| `ref_catalog` incomplet (parent negăsit pentru unele $ coduri) | Medie | Articolele fără parent în catalog rămân în `ref_dedup_main` → procesate normal în Layer 1-4 |
| Colizii cheie (același $cod, deviz, parent dar cantități diferite) | Scăzută | N:M pairing în Layer 0 (la fel ca Layer 1) |
| Regresii în matched count | Scăzută | Testăm explicit că matched ≥ v7.0 baseline |
