## Obiectiv

Reproiectarea a trei componente interdependente:
1. **Structura de date** — adăugare `nr_ordine`, `parent_cod`, moștenire cant/UM
2. **Logica de matching** — ancorare pe referință, eliminare `ARTICOL_ORPHAN`, matching ierarhic
3. **Raportul DOCX** — ierarhic, devize în ordinea referinței, neconformitate marcată inline

### 1.1 Câmpul `nr_ordine`

- Tip: `int` (1-based) pentru articole principale; `str` pentru subarticole (`"3.1"`, `"3.2"`, sau doar .L spre exemplu , trebuie descoperita regula )
- Sursa: coloana "Nr." / "Nr.crt." din tabelul F3 ; sau ceva ce poate fi considerat nr de ordine 
- Fallback: numărare secvențială în ordinea apariției în deviz dacă coloana lipsește, corect ; insa nu ar trebui sa exista fara numerotare in referinta si nici in oferte
- Subarticolele moștenesc nr_ordine al părintelui + suffix secvențial; corect insa trebuie extras daca exista 

### 1.2 Câmpurile `parent_cod` și `parent_nr_ordine`

- Prezente DOAR la subarticole (`is_component=True`)
- La articole principale: `parent_cod = None`, `parent_nr_ordine = None`
- Valori: codul și `nr_ordine` al articolului principal imediat precedent în același deviz

### 1.3 Moștenire cant/UM pentru subarticole

Dacă subarticolul are `cantitate=0` sau `um=""`:

```python
def _apply_parent_inheritance(articole: list) -> list:
    current_parent = None
    for art in articole:
        if not art.get('is_component'):
            current_parent = art
        elif current_parent:
            art['parent_cod'] = current_parent.get('cod')
            art['parent_nr_ordine'] = current_parent.get('nr_ordine')
            if not art.get('cantitate') or not art.get('um'):
                art['cantitate_originala'] = art.get('cantitate')
                art['um_originala'] = art.get('um')
                art['cantitate'] = art.get('cantitate') or current_parent.get('cantitate')
                art['um'] = art.get('um') or current_parent.get('um')
                art['cant_mostenita'] = True
    return articole
```

Apelată în `f3_extractor.py` după parsare, înainte de deduplicare.

## Pas 2 — Logica de Matching

### Fișiere modificate
- `AgentComparator_local.py` (principal)
- `shared/comparator.py`

### 2.1 Principiu fundamental

**Matching pornește ÎNTOTDEAUNA din referință.**

| Situație | Clasificare v6 | Clasificare v7 |
|----------|---------------|---------------|
| Articol ofertă dintr-un deviz fără corespondent în ref ,deviz | `ARTICOL_ORPHAN` | `ARTICOL_EXTRA` |
| Articol ref dintr-un deviz fără corespondent în ofertă /deviz | `ARTICOL_LIPSA` | `ARTICOL_LIPSA` (neschimbat) |

`ARTICOL_ORPHAN` se elimină complet din codebase.

### 2.2 Matching ierarhic Principal → Subarticole

```python
for deviz in devize_referinta:  # în ordinea referinței
    for principal_ref in articole_principale_ref[deviz]:
        principal_oferta = find_match(principal_ref, articole_oferta[deviz])
        if principal_oferta:
            for sub_ref in subarticole_ref[principal_ref.cod]:
                sub_oferta = find_match(
                    sub_ref,
                    subarticole_oferta_in_context(principal_oferta)
                )
```

Straturile Layer 1-3 existente se aplică la matching principal. Subarticolele se caută întâi în contextul principalului matched, apoi global în deviz (fallback). obseerrvatie ; orice cautare trebuie sa se intample in cadrul unui deviz ; mai exact cheia de cautare este mereu deviz+cod articol principal + cod articol secundar .  ( un articol secundar - subarticol trebuie mereu sa aibe articol principal setat )  ;   daca am avea un articol secundar fara articol principal, extras  , il vom afisa la sfarsitul raportiului ca erorii de extractie /ocr .

### 2.4 Fix deduplicare O(n²) → O(n)

```python
def _deduplicate_neconformitati(neconformitati: list) -> list:
    priority = {'COD_SIMILAR': 3, 'DIFERENTA_CAMP': 1,
                'UM_DIFERIT': 1, 'ARTICOL_LIPSA': 0, 'ARTICOL_EXTRA': 0}
    best: dict = {}
    result_indexed = {}
    for nc in neconformitati:
        key = (nc.get('deviz', ''), nc.get('ref_cod', ''), nc.get('oferta_cod', ''))
        curr_p = priority.get(nc.get('tip', ''), 0)
        if key not in best or curr_p > best[key]:
            best[key] = curr_p
            result_indexed[key] = nc
    return list(result_indexed.values())
```

### 2.5 Subarticole fără articol principal (erori de extracție)

Dacă extracția produce un subarticol (`is_component=True`) cu `parent_cod=None`:
- Nu participă la matching normal
- Colectat într-o listă separată: `erori_extractie_ocr`
- Afișat la finalul raportului DOCX într-o secțiune dedicată: **"Erori de extracție / OCR"**
- Format: cod, denumire, deviz, pagina sursă (dacă disponibilă)
- Nu generează `ARTICOL_LIPSA` sau `ARTICOL_EXTRA`

### 3.2 Structura DOCX

**Per deviz** (în ordinea referinței):
```
═══════════════════════════════════════
DEVIZ: 226108 — Structură de rezistență
Matched: 120  |  Lipsă: 3  |  Extra: 5
═══════════════════════════════════════

[1] TF24A — Turnare beton armat C25/30
    Ref: 34.2 mp  |  Ofertă: 34.2 mp  |  ✓ MATCHED

    [1.1] $3274270 — Cofraj lemn ecarisat
          Ref: 102.6 mp  |  Ofertă: 102.6 mp  |  ✓ MATCHED

    [1.2] $3274271 — Armatura OB37             ⚠ DIFERENTA_CANTITATE
          Ref: 850 kg  |  Ofertă: 420 kg
```

**Reguli afișare:**
- Articolul principal apare **întotdeauna** ca header al blocului, chiar dacă este MATCHED
- Principalul apare în bloc DOAR dacă are cel puțin un subarticol cu neconformitate SAU el însuși are neconformitate
- Dacă principalul și toate subarticolele sale sunt MATCHED → bloc omis din raport (nu apare)
- Neconformitatea marcată cu `⚠` bold/roșu pe rândul subarticolului afectat
- Devizele fără nicio neconformitate → secțiune sumar minimal (1 linie: "Toate articolele conforme"), si nr de articole principale , pentru a putea verifica

## Constrângeri

- Raportul DOCX existent rămâne funcțional după Pas 1 și 2 (gardul de regresie)
- Nu se generează Excel
- `ARTICOL_ORPHAN` dispare complet (nicio referință rămasă în codebase)
- Ordinea devizelor în DOCX = ordinea din referință (nu alfabetică, nu după cod)
- Blocul principal apare în raport DOAR dacă există neconformitate (la el sau subarticole)
